NUTS as Smart Trajectory Construction

From HMC to U-turn checks to dyadic interval reductions

A conceptual route from Metropolis-Hastings correctness to dynamic HMC trajectories.

The goal is to make NUTS feel like a principled construction problem rather than a mysterious recursive algorithm.
Reminder

Metropolis-Hastings is about valid transitions

Given a proposal foobar \(q(x,y)\), accept \(y\) with probability

\[ \alpha(x,y) = \min\left( 1, \frac{\pi(y)q(y,x)}{\pi(x)q(x,y)} \right). \]

The transition kernel must preserve the target.

\[ \pi(x)K(x,dy) = \pi(y)K(y,dx). \]

MCMC correctness depends on useful proposals and target-preserving transitions.

This is the bridge: NUTS is not only a clever way to move far. It must construct a valid Markov transition.
Motivation

HMC replaces random walks with dynamics

Random-walk proposals often move slowly in high dimensions.

HMC augments position \(q\) with momentum \(p\).

\[ \pi(q,p) \propto \exp[-H(q,p)] \] \[ H(q,p) = U(q) + K(p) \] \[ U(q) = -\log \pi(q) \]

HMC uses approximate physical dynamics to propose distant, informed moves.

Vanilla HMC

The standard recipe

Sample momentum \(p \sim N(0,M)\).

Simulate Hamiltonian dynamics for \(L\) leapfrog steps.

Propose the final phase-space point \((q',p')\).

Accept or reject using the Hamiltonian error.

\[ \alpha = \min\left(1,\exp[-H(q',p') + H(q,p)]\right). \]

Validity comes from approximate energy preservation, volume preservation, reversibility, and MH correction.

Integrator

Leapfrog integration

\[ (q_t, p_t) \xrightarrow{\phi^V_{\epsilon/2}} (q_t, p_{t+\epsilon/2}) \xrightarrow{\phi^T_{\epsilon}} (q_{t+\epsilon}, p_{t+\epsilon/2}) \xrightarrow{\phi^V_{\epsilon/2}} (q_{t+\epsilon}, p_{t+\epsilon}) \]
\[ \begin{aligned} p_{t+\epsilon/2} &= p_t - \frac{\epsilon}{2}\nabla U(q_t),\\ q_{t+\epsilon} &= q_t + \epsilon M^{-1}p_{t+\epsilon/2},\\ p_{t+\epsilon} &= p_{t+\epsilon/2} - \frac{\epsilon}{2}\nabla U(q_{t+\epsilon}). \end{aligned} \]
symplectic reversible with momentum flip volume preserving stable for long trajectories
Tuning

Vanilla HMC asks for a trajectory length

Step size \(\epsilon\)

Controls numerical stability.

Number of steps \(L\)

Controls how far the proposal moves.

Too short

  • random-walk-like behavior
  • high autocorrelation

Too long

  • trajectory may loop back
  • wasted computation
  • endpoint may not be far away

The hard tuning problem is choosing a useful trajectory length.

Geometry

U-turn intuition

\[ (q_b-q_a)^T p_a < 0 \quad\text{or}\quad (q_b-q_a)^T p_b < 0. \]

The endpoint displacement is opposed to an endpoint momentum: the path is doubling back.

Caution

Naive stopping is dangerous

Tempting rule

"Integrate forward until the trajectory makes a U-turn, then stop."

The stopping rule may depend on the current state's forward view of the trajectory.

From a proposed state inside the same path, the generated candidate trajectory may differ.

Dynamic stopping must be designed so the transition remains reversible and target preserving.

This slide should prevent the common misconception that NUTS is simply HMC with a while-loop.
Cost

Checking every interval is expensive

Suppose an HMC path has states

\[ z_0, z_1, \ldots, z_{n-1}. \]

A maximally cautious check would test every interval \([i,j]\).

\[ (q_j-q_i)^T p_i < 0 \quad\text{or}\quad (q_j-q_i)^T p_j < 0. \]
\[ \binom{n}{2} = O(n^2). \]

Naively checking all possible subtrajectories is too expensive.

Design target

What NUTS needs to achieve

Computational problem

Avoid exhaustive \(O(n^2)\) U-turn checking.

MCMC correctness problem

Construct a dynamic trajectory compatibly with reversibility.

The binary tree organizes trajectory construction so dynamic stopping can be efficient and correct.

Growth

Growing the orbit around \(z_0\)

\(I_0 = \{0\}\)

Add one state left or right.

Add a block of size \(2\).

Add 2 states left or right.

Add a block of size \(4\).

Repeat until a U-turn or divergence stops expansion.

\[ I_{k+1} = \begin{cases} I_k^{\mathrm{new}} \cup I_k, & \text{if extending left},\\ I_k \cup I_k^{\mathrm{new}}, & \text{if extending right}. \end{cases} \]

NUTS grows an interval using random dyadic expansions.

NUTS tree

Dyadic chunks: 1, 2, 4, 8, ...

At each doubling, NUTS randomly chooses to extend left or right.

NUTS constructs a balanced binary tree over a finite interval of the Hamiltonian orbit.

Same orbit, different root

Orbit invariance

\[ [0:7] \sim [-2:5] \] \[ \bar z_i = z_{i-2} \iff z_j = \bar z_{j+2} \]
\[ P_h(J \mid z_0) = P_h(J-2 \mid z_{-2}) \]
\[ \mathbb P\big([+1,+1,+1]\big) = \mathbb P\big([+1,-1,+1]\big) \]

\(P_h\) needs this re-rooting symmetry in its interval accounting for detailed balance to hold.

Efficiency

NUTS does not store every possible interval

Naive idea

Store every subinterval \([i:j]\) and every state that could later be drawn from it.

\[ \#\{\text{intervals}\} = \binom{n}{2} = O(n^2) \]

NUTS strategy

Store only dyadic interval summaries and one running proposal summary for each merged block.

\[ \#\{\text{tree nodes}\} = O(n) \]

to
discard raw interval alternatives

NUTS never needs a catalog of all admissible subintervals. It keeps only enough aggregated information to stop correctly and sample one proposal with the right weights.

The tree

A linear sequence becomes nested subtrees

Each new integration state extends the line, and whenever an interval closes, its subtree summary appears immediately.

Abstraction

The tree is an evaluation order

\[ \operatorname{summary}([a,c]) = \operatorname{summary}([a,b]) \oplus \operatorname{summary}([b+1,c]). \]

For addition, \(\oplus = +\).

\[ (A \oplus B) \oplus C = A \oplus (B \oplus C). \]

Associativity allows local pieces to be reduced into larger interval summaries.

Internal checks

U-turn checks happen at internal nodes

\[ \operatorname{turn}_{a:b} = \operatorname{turn}_{a:m} \vee \operatorname{turn}_{m+1:b} \vee \operatorname{cross\_turn}_{a:b}. \]
\[ \operatorname{cross\_turn}_{a:b} = \left[(q_b-q_a)^T p_a < 0\right] \vee \left[(q_b-q_a)^T p_b < 0\right]. \]

Large-scale turning can appear even when smaller intervals look locally valid.

Efficiency

Structured checks replace exhaustive checks

Naive

Check all intervals \([i,j]\).

\(O(n^2)\)

NUTS tree

Check intervals corresponding to dyadic tree nodes.

\(O(n)\)

\[ \text{binary tree with } n \text{ leaves} \quad\Rightarrow\quad O(n) \text{ nodes}. \]

The tree gives an efficient family of multi-scale U-turn checks.

Selection

NUTS does not simply return the final endpoint

It constructs a candidate set along the trajectory and samples from it.

\[ w_j \propto \exp[-H(z_j)] \]

For multinomial NUTS, candidates are weighted by their phase-space density.

Reversibility

The segment must make sense from inside itself

The selected trajectory segment must be coherent from the original state.

It must also be coherent from a possible proposed state inside the same segment.

NUTS is a carefully designed dynamic MH transition, not merely "stop when the path turns."

Summary

Why NUTS is smart

It avoids manual trajectory-length tuning.

It detects wasted computation through U-turn checks.

It avoids exhaustive \(O(n^2)\) checking using dyadic interval reductions.

It preserves MCMC correctness through symmetric construction and careful proposal selection.
